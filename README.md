# 太阁资料工坊 · Taikou ROM Studio

独立的浏览器 ROM 资料查阅与单条编辑工具。所有 ROM 字节留在浏览器本地，不会上传或随项目分发。

- 本地项目：`/Users/joenix/Game/@小咪优化/taikou-rom-studio`
- GitHub：`https://github.com/joenix/taikou-rom-studio`
- 网页：`https://joenix.github.io/taikou-rom-studio/`

## 使用

1. 载入未压缩的 MD 太阁 `.bin` / `.md` / `.gen` ROM。
2. 通过游戏标识、关键读取指令、完整记录结构及 MD 校验和检查后，开放查阅。
3. 顶部切换查阅 / 编辑；查阅和筛选状态保持。点击单条详情里的编辑按钮，也会切入编辑模式并打开弹窗。
4. 单条弹窗中修改、取消或应用；失败时原子拒绝，不写入部分字段。
5. 可撤销、重做。最后导出新的 `_edited.bin`，原始文件不被覆盖。

查阅内容为 ROM 的初始设定，不是玩家存档中的当前世界。713 是武将记录数，不代表运行时同时登场人数。势力关联驻城不等于城池所有权。

## 第一阶段范围

| 资源 | 查阅 | 单条编辑 |
|---|---|---|
| 武将 | 姓名、六维、八项技能、初始身份/势力/居城、等级、经验、相性原码 | 姓名、六维、七项技能、相性低四位 |
| 宝物 | 名称、基础价值、类别原码、已确认武具品阶、初始实例引用 | 名称、+11 单字节基础价值 |
| 城池 | 名称、初始驻将、只读邻接候选 | 名称 |
| 势力 | 武将初始势力编号关联汇总 | 只读 |

文化技能、出仕/身份/居城变更、经验规则、头像、地图和剧情暂不开放写入。每次事务只绑定一个资源类别和一个记录 ID，不能批量修改或导入任意字节补丁。

能力的编辑范围为 0–255（字节范围），不等同于游戏内成长上限；100 以上实际效果由对应 ROM 规则决定。Shift-JIS 不能编码的名称字符或超长文本会明确报错，不会截断或替换成乱码。

## 校验原则

- 依据本地九个文件核验过的共同数据布局（八个不同 SHA-256）；v1.26 与 v1.30 在现有库中内容完全相同。
- SHA-256 用于记录文件身份；它不是唯一准入条件，编辑后生成的文件也应能重载。
- 游戏国内标题的原始标识包含历史错字，按核验过的实际字节判断，不能用纠正后的展示名称替代二进制标记。
- 关键代码签名、表结构、名称编码、ID、引用、等级和宝物保留字节任一失败，抛出带错误码和定位信息的异常。
- 导入时要求 MD 校验和正确。工作副本允许校验和暂未更新，导出时重新计算并再次校验。
- 校验通过代表满足当前解析规则，并不证明未知版本的全部游戏机制与原版一致。

新布局需要补充独立 profile 和验证样例，不能自动猜偏移。支持的功能按已确认字段扩展。

## 开发

Node.js 22+：

```bash
npm ci
npm run dev
npm test
npm run build
npm run inspect -- /你的路径/游戏.bin
```

开发地址：`http://127.0.0.1:5173/taikou-rom-studio/`。生产构建在 `dist/`，推送到 `main` 后 GitHub Actions 自动测试并发布 Pages。项目没有 AI API 调用或文件上传接口。

测试使用程序生成的合成字节样例，不包含游戏 ROM。覆盖版本/结构异常、旧价格字段损坏、字段范围、编码长度、单条事务、保留位、撤销重做、导出校验和与重载。

## 结构

- `src/rom/profile.js`：当前已核验布局、签名与字段标签。
- `src/rom/validate.js`：导入和导出校验。
- `src/rom/codec.js`：二进制与文本编码、异常和校验和。
- `src/rom/document.js`：不可变原始 ROM、工作副本、单记录写入白名单、事务与导出。
- `src/App.jsx`：查阅工作台和单条记录编辑弹窗。
- `docs/roadmap.md`：后续头像、地图与剧情的分阶段路线。
- `docs/evidence.md`：本阶段的数据证据和有意锁定的功能。

数据地址与部分编码思路参考本地 `Taiko_Editor_v2.5.html`，重新实现事务和校验，并修复宝物基础价值 +10/16 位的旧写法。原编辑器和 ROM 不作修改。
