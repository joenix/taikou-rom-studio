# 太阁资料工坊 · Taikou ROM Studio

独立的浏览器 ROM 资料查阅与单条编辑工具。所有 ROM 字节留在浏览器本地，不会上传或随项目分发。

- GitHub：`https://github.com/joenix/taikou-rom-studio`

## 使用

1. 载入未压缩的 MD 太阁 `.bin` / `.md` / `.gen` ROM。
2. 通过游戏标识、关键读取指令、完整记录结构及 MD 校验和检查后，开放查阅。
3. 默认浏览模式。桌面点击右上角钥匙并输入密码后解锁编辑；移动设备只读。
4. 单条弹窗中修改、取消或应用；失败时原子拒绝，不写入部分字段。
5. 可撤销、重做。最后导出新的 `_edited.bin`，原始文件不被覆盖。

查阅内容为 ROM 的初始设定，不是玩家存档中的当前世界。713 是武将记录数，不代表运行时同时登场人数。势力关联驻城不等于城池所有权。

文化技能、出仕/身份/居城变更、经验规则和剧情不开放写入。每次事务绑定一个资源类别和一个记录 ID，不能导入任意字节补丁。新增人物/宝物及运行时数量上限解除尚未实现。

2026-11-04 修正头像引用为 `0x85D30 + 16*人物ID`。若曾用旧版修改并导出头像，请从修改前的 ROM 重新设置；旧导出文件不自动修复。证据与边界见 [头像说明](docs/portraits.md)。

## 校验原则

- 当前接受通过 v1.40.02、v1.40.17 独立关键代码签名与结构验证的布局，及通过初始化入口定位并校验 FEX1 数据区的 v1.42 ROM；不按文件名猜版本。
- 新构建优先读取 ROM 内 `TKROMD01` 资源目录；发行版号与数据布局 `profile_id` 分开，具备相同数据 schema 的小版本复用同一适配。详见 [ROM 目录标记协议](docs/rom-directory.md)。
- SHA-256 用于记录文件身份；不是唯一准入条件，编辑后生成的文件也应能重载。
- 游戏国内标题的原始标识包含历史错字，按核验过的实际字节判断，不能用纠正后的展示名称替代二进制标记。
- 关键代码签名、表结构、名称编码、ID、引用、等级和宝物保留字节任一失败，抛出带错误码和定位信息的异常。
- 导入时要求 MD 校验和正确。工作副本允许校验和暂未更新，导出时重新计算并再次校验。
- 校验通过代表满足当前解析规则，并不证明未知版本的全部游戏机制与原版一致。

新布局需要补充独立 profile 和验证样例，不能自动猜偏移。支持的功能按已确认字段扩展。

## 结构

- `docs/roadmap.md`：历史阶段计划；当前能力以本说明和源码为准。
- `docs/evidence.md`：本阶段的数据证据和有意锁定的功能。

数据地址与部分编码思路参考本地 `Taiko_Editor_v2.5.html`，重新实现事务和校验，并修复宝物基础价值 +10/16 位的旧写法。原编辑器和 ROM 不作修改。
