# v1.42 FEX1 势力数据适配

## 当前支持

编辑器通过 ROM 标题与新游戏初始化跳转定位 `FEXInitializeFromROM`，再解析其中 PC 相对指针指向的默认数据块；不依赖 ROM 文件名或固定追加长度。数据区布局采用 rebuild 的 FEX1 payload 约定：

| 内容 | 相对 payload 偏移 | 记录数 | 单条字节 |
|---|---:|---:|---:|
| 扩展势力记录 | `0x000` | 18（ID 20–37） | 34 |
| 扩展城池记录 | `0x264` | 36（ID 123–158） | 18 |
| 原势力→扩展势力关系 | `0x4EC` | 20×18 | 1 |
| 扩展势力→扩展势力关系 | `0x654` | 18×18 | 1 |
| 稳定首领人物 ID | `0x798` | 18 | 2 |
| 稳定城主人物 ID | `0x7BC` | 36 | 2 |

姓名、计划首领身份名、据点名称来自 `src/rom/faction-expansion-v142.json`。该标签文件记录了 rebuild 结构化清单的 SHA-256；实际 ID、关系和记录值仍从所载 ROM 解析。

## 编辑范围

- 扩展势力可编辑首领候补（选择现有人物 ID）与本城（限于该势力所属扩展据点）。同一人物不能同时被多个扩展势力选作首领候补。
- 原版势力只读。
- 36 个扩展城池的 ROM 记录可按势力查看名称、候补城主和归属，但尚不支持编辑城池字段或地图坐标。
- 扩展势力关系为只读显示，分别展示双方默认关系；不把空白/未接通数据误称为游戏中的实时外交状态。
- 修改写入 ROM FEX1 默认 payload，支持撤销、重做和导出校验和。新游戏初始化会复制这块默认数据到 SRAM；历史存档不做兼容迁移。
- 势力列表选中扩展势力后，右侧显示 ROM 中的首领／城主候补，并链接到对应人物记录。
- 详情另列人物编制草案中的 23 个拟用人物槽位，显示“目标身份 → 当前人物槽位”。数据来自 `taikou-rebuild/reports/map-expansion-faction-personnel-design.json`，仅供查阅，不写入 ROM，也不计作游戏内在编武将。runtime ID 24、28、31 的旧草案身份已与当前势力稿不一致，因此不自动挂载旧成员建议。

## 重要限制

v1.42 当前只接通 FEX1 默认数据初始化与存档读写。游戏的势力、城池和人物消费者仍走原版运行路径，因此 18 家扩展势力及 36 个扩展城池目前**不会在游戏中登场或参与运算**。编辑器写入扩展数据可以为后续运行逻辑保留并调整方案数据，但不会令当前 ROM 变成可玩新势力版本。

## 武将列表：仅新武将

「仅新武将」开关按ROM目录 `resident_sources` / `resident.batch-bindings.v1` 里的实际静态人物来源识别，当前41人。不是按人物ID区间、低能力、计划编制名单或当前静态势力号推测；解析来源地址、步长、范围、人物ID和重复引用。数据标记 `isNewOfficer` 由 `src/rom/new-officers.js` 与document提供，App只做筛选，可叠加搜索、生年、能力、技能等现有条件。再次点击、重置筛选或切换模块恢复全部；切换开关回第一页。移动端在筛选区同样可浏览使用。实际ROM结果与rebuild的41条assignments逐项一致，专项测试和生产构建通过。仅本地修改。

### v1.42.24 新头像

41名新武将的内置直接/合成头像引用由rebuild统一分配，编辑器按人物记录的真实selector渲染，无需按版号新增偏移表。武将详情、头像选择器、仅新武将筛选共用同一ROM数据。tests/faction-portraits.test.js核对41个实际引用、与672个原版人物及彼此的渲染哈希不重复、导出字节相同，以及新版本地图/寻路读取。素材由原生游戏33BA/E136例程逐个比对。选择理由的权威来源是rebuild/assets/data/faction-portraits-v142.json，不使用旧候补名单中的portrait_selector覆盖。

v1.42.25：島津義弘引用改为34775（红色战盔浓须）。201因用户反馈与其主角冲突，作为新武将分配禁用引用；不据此推定静态人物0当前使用201。编辑器从新ROM读取，无按版号的渲染分支。
