# 一屏资料工作台：界面讨论（2026-11-03）

本次只实现人物列表列项和合并地图入口；下面的布局方案尚未实现。审视当前Chrome内本地资料工坊，使用本轮实际截图。用户选择讨论方案，未进行整站视觉重做、系统框架更换或发布。

## 1. 地图浏览：需要改善

强项：真实原画、目录和地图选中联动已可用；无需理解地形编号即可识别地点。
问题：截图中地图占满工作区下半屏，选中地点详情在地图下面，首屏无法看到；顶部文件行、页标题和多层工具行占用不少高度。
建议：目录／地图／地点详情并排；右侧详情固定，地图在中心自适应剩余高度。地图工具在同一模块，不另立工坊入口。
可访问性风险：小倍率下城町命中范围很小，触屏与精细定位不易操作；目录是现有替代入口。键盘与屏幕阅读器完整流程本次未验收。

## 2. 人物资料列表：需要改善

强项：表格、筛选、分页与详情并列；单记录编辑按钮已固定在详情底部，不应退化为跟着长内容滚走。
问题：当前截图首屏只显示约5行完整记录；右侧头像和大标题占用较多高度，能力技能在折叠屏以下，需要在详情内部滚动才能看到。
建议：压缩工具与标题区域、列表行高，保留每页100条；头像缩小并与姓名/身份并排。右侧以概况、能力技能、关联切换内容，长期保持条目标题和主要操作可见。
可访问性风险：辅助文字偏小且颜色较浅；截图不能确定所有对比度是否达标，后续需量测。不能用只保留无文字图标的方式压缩所有入口。

## 3. 人物编辑：主要问题

强项：应用/取消在弹窗固定底部，头像是真实图像且按需加载。
问题：头像预览、搜索和列表占据编辑弹窗首屏；用户打开“编辑武将”后，看不到姓名、能力、技能输入。头像列表滚动叠加弹窗滚动，使后面的字段不容易被发现。
建议：普通编辑在固定右侧属性面板进行，头像选择单独打开选择面板；能力、技能等分小页，避免纵向串联所有资料。应用/取消保持固定。切换记录时明确处理未应用草稿，不能静默覆盖。
可访问性风险：嵌套滚动与焦点位置可能增加键盘操作负担；本次截图与浏览器检查不足以证明完整辅助技术兼容。

## 4. 本轮已落地的小改：已验证

人物列从武力/统率改为相性、战术等级、政略等级；相性保持0～15原码，不伪称武将之间的好感。排序入口同步增加战术/政略；数值筛选改为相性。未改ROM数据。当前截图表格宽度947px，内容宽度947px，无新增横向滚动。

去掉侧栏“地图工坊”，只保留地图。解锁后可在地图模块进入“编辑地形与位置”，复用已有事务和权限；锁定后回到地图浏览。嵌入模式不显示重复大标题。浏览器已核对新列、单入口、进入工具与锁定返回，未应用ROM变更。

## 推荐方向：桌面资料编辑工具

固定一屏外壳：紧凑顶部工具栏＋模块导航＋中间工作区＋右侧属性面板＋底部状态栏。仅数据列表、地图画布和必要的面板内容局部滚动；主要操作、分页和内容切换入口固定。

保留现有字体、酒红品牌色和真实游戏资源。减少大标题、层层卡片、重复说明和留白，不先更换技术框架。人物详情分概况/能力技能/关联，地图详情固定右侧，势力在主工作区提供概况/外交/武将；不把17家关系和长武将名单一起塞进窄侧栏。

先改人物页作为样板，确认密度和交互，再推广到宝物、地图、势力。该整站布局方案当前只是讨论建议，尚未实施。截图只覆盖本轮桌面视口；手机、完整键盘和辅助技术、对比度标准尚未全面验证。
