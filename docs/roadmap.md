# 分阶段路线

## 阶段一：资料查阅与精细编辑（当前）

默认查阅；编辑模式保留所有查阅功能，只增加单条记录弹窗。支持武将、宝物、城池、初始势力汇总；改动前后均校验，不开放任意偏移或批量写入。

后续先围绕用户实际使用反馈调整检索维度，并逐项补充字段。新增字段必须有地址、宽度、编码、语义、适用布局、证据和事务约束。

## 阶段二：关联数据与头像

先验证物品实例的持有人/商店和标志位；再讨论所持编辑。身份、转籍、继任等涉及跨记录一致性的功能不能伪装成修改一个字节。

头像先按 ROM 原始选择器与调色板还原，证明只读解码正确，再开放资源引用或写回。

## 阶段三：地图

分别建立世界地形、位置、通行/碰撞、场景图块、调色板的解析规则与验证样例。地图不是当前城池表的同义词。

顺序：只读解码 → 无修改往返导出 → 点位/路径单对象编辑 → 地形和图块编辑。压缩资源需验证解压/重压缩一致性、容量、指针修复与旧区域保护。

UI 将新增地图工作区，但仍复用 ROM 工作副本、校验、事务历史、撤销与导出；地图操作以单个对象或明确选区为一个事务。

## 阶段四：文本与剧情

从文本和资源引用查阅开始，再核验事件条件及动作。原版可能包含直接的 68000 逻辑，不能预设存在统一事件脚本格式。

需要运行时验证的字段，请用户提供指定场景的存档副本，说明要核对的现象。原始存档和原始 ROM 不被覆盖。

2026-10-31：用户选择优先真实增删引擎研究，地图界面暂缓。已证明第 21 入口可被原生函数识别；独立新町场景、回程重定向、城 RAM 扩容与存档迁移仍未实现。详见 [地图引擎研究](map-engine-research.md)。
