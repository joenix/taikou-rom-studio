# 地图引擎增删研究

用户已选择先研究真实新增、删除写回，界面后做。当前只有底层地图事务和原生函数实验，网站尚未开放地图按钮。界面草稿保留在本地 Git stash（`WIP map UI deferred`）。

## 已证明的范围

大地图由 41 × 24 个分区组成，每区 8 × 8 格，总计 328 × 192 格。其中 521 个分区分配了独立数据块。它不同于势力总览图。

| 资源 | ROM 地址 | 结构 |
| --- | --- | --- |
| 大地图分区索引 | `0x764A8` | 前 984 个大端 word；零表示未分配 |
| 大地图格数据 | `0xC0826` | 521 × 64 字节；原码，不推断地形语义 |
| 城池定义 | `0x77952` | 125 × 20 字节；仅 123 个活跃城 ID |
| 城位置 | 城定义 +14 | 分区 word、局部 X/Y 两字节 |
| 城池运行数据初值 | `0x7AAB8` | 123 × 18 字节，初始化到 `0xFF3D6C` |
| 町内部地图基址 | `0x761C6` | 17 × word，每町 3 组 × 4 个内部地图 |
| 町名称指针 | `0x75D36` | 17 × long，零终止 Shift-JIS 文本 |
| 町入口 | `0xD30DA` | 20 × 8 字节，世界来源四字节、内部目标四字节 |
| 町入口附加标志 | `0xD317A` | 20 字节，原生进町路径读取 |
| 势力总览城坐标 | `0xBFCDC` | 123 × 2 字节，与行走地图独立 |

京都、難波、堺有两个入口。目加田/安土、 本願寺/大坂共用世界坐标，后两条剧情异名不是空闲城槽位。普通地形编辑禁止覆盖城/町标记，移动地点必须明确指定旧址回填原码。

从用户已有存档副本进入行走地图后，RAM 中周围 9 个分区与 ROM 数据逐格比较，屏蔽运行时城池配色位后 **0 处不一致**。见 [分区证据](evidence/map-runtime-blocks.json)。本地库中 9 个太阁文件均通过本次地图结构检查；这不代表新增引擎补丁对全部版本已验收。

## 原生实验结果

实验基底 SHA-256：`1914e94a23d54d6e6e797d5d97ebd17fb8d5017f6a75d9b89e656590ffbe4975`。

1. 将入口表迁移到 ROM 尾部，保留原 20 项，加入第 21 项。同步迁移三处直接用户、以表首减 8 为基准的回程用户、附加标志表，并扩展两处循环边界。原生 `0xF98A` 与 `0xF9F0` 均能识别第 21 个入口，现有入口与回程查找仍正确。
2. 单独扩展町地图分类表到 18 项，原生 `0x746E` 对实验新地图族的 12 个变体均返回新 ID 17。**此实验地图族没有分配场景，不可进入，不构成独立新增町。**
3. 停用第 0 町入口并回填地形，两条原生进町函数均不再进入。但原生 `0xF914` 出町查找返回 `0xFFFF`，说明单纯擦入口会破坏回程，不能交付为删除功能。

证据：[入口扩展补丁](evidence/map-entry-extension.json)、[停用实验](evidence/map-entry-disable.json)、[原生探针结果](evidence/map-native-probes.json)。所有 ROM 与存档实验均用副本，不提交 ROM 二进制。

## 城池扩容的硬约束

`0x17DC8` 将城 RAM 初始化长度设置为 `0x8A6 = 123 × 18`，起点 `0xFF3D6C`，结束恰为 `0xFF4612`；紧接着 `0x17DD6` 就初始化从 `0xFF4612` 起的另一块 `0x5C4` 字节数据。直接把城数改成 124 会侵入相邻数据，不能只增加循环次数。

世界城识别 `0xF63E`、地图配色 `0xC286`、领地遍历 `0x76A6` 等都硬编码 123。静态表还有大量绝对引用。真正新城需要 ROM 定义、运行数据、初始化、AI/路线、势力总览和持久化一起扩展。当前没有证据证明 RAM 后面有安全可用空位。

## 实施设计与先后顺序

先完成一个独立新町的闭环，再做新城，避免同时迁移城池运行数据。

- **稳定 ID**：删除使用停用标志，已有地点不重排，防止人物、商店、剧情引用整体错位。停用的地点不能自动当作无引用空位。
- **新增町模板**：明确复制哪个内部场景；为地图分区索引、内部 12 个变体、名称、入口、出口、商店/设施分配独立资源。模板复制不等于共用商店状态。
- **删除前检查**：列出驻将、人物所在地、任务目标、商店及设施、路线和出入口。必须指定迁移地点或拒绝删除；未知剧情引用默认阻止“已安全删除”结论。
- **回程改造**：新入口和町身份分离，显式指定主出口；停用后禁止返回无效分区，为当前驻留者和旧存档定义迁移规则。
- **补丁适配**：按基底布局及指令指纹识别，分配空间时检查占用。已打扩容补丁的 ROM 需要新的布局版本，不能继续冒用原版固定数量。
- **旧存档**：新增地点涉及持久化结构，必须有版本及迁移策略。游戏内存档和模拟器即时存档分开验收；目前均未完成。

验收关卡：新町在新坐标显示 → 进入独立内部场景 → 店铺/设施独立 → 从各出口返回新坐标 → 保存重开后保持 → 停用时迁移驻留人物与目标 → 最后接前端。每关必须有原生运行证据，不能用前端列表新增一条代替。

前端随后提供：地点列表与地图联动、点击单地点弹窗、放置冲突提示、旧址回填选择、矩形地形选区与吸取、分区网格、引用检查、原子事务、撤销重做、导出前修改清单。原画图块和碰撞语义仍需另行解码；逻辑格配色必须标明不是原画。

```sh
npm test
node tools/research/map-engine.mjs /absolute/path/base.bin /tmp/extra-entrance.bin > /tmp/extra-entrance.json
node tools/research/map-engine.mjs /absolute/path/base.bin /tmp/disabled-entrance.bin disable > /tmp/disabled-entrance.json

```

生成器拒绝覆盖现有输出或输入，先校验 ROM 与每处补丁指令，最后修复 MD 校验和。探针依赖本地已有的调试 Genesis Plus GX 核心和兼容存档副本，使用该 emulator 模块所需的 NumPy/Pillow；CI 只跑合成 ROM 单元测试，不包含用户游戏或外部核心。
